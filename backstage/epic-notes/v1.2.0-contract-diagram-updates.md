## Tasks from Triage

### 1. Mermaid Lint/Check
**Goal:** Prevent broken diagrams, enforce standards.

**Requirements:**
- No fancy characters (ASCII only)
- Valid classDef syntax (`classDef` + `class`, not `:::inline`)
- Exit code validation (valid/invalid)

**Research:**
- Mermaid CLI (`mmdc`) validation options?
- Custom rules engine?
- Pre-commit hook?

### 2. Git Timeline Navigation (Topic 4)
**Goal:** Range slider to navigate commit history of diagram.

**Features:**
- Slider shows evolution (rewind user-controlled)
- Branch history = granular (all commits)
- Main history = snapshots only (merge commits)
- Load diagram at specific commit

**Implementation:**
- Fetch commit list via GitHub API or git log
- Render diagram from historical MD content
- Slider maps positions to commits

---

### 3. Domain System (Topic 10)
**Goal:** Departments/disciplines claim nodes, become stakeholders.

**Domains:**
- Front-end
- Back-end
- Legal
- Compliance
- Design
- Security

**Flow:**
1. Node has domain tag (e.g., `class NODE1 front-end`)
2. Domain SEES contract (scans all contracts)
3. Domain CLAIMS nodes (if domain tag present)
4. If domain claimed nodes → domain = stakeholder (must participate supervised)

**Parallel approval:** All domains approve simultaneously (not cascading).

**Blocker rights:** Domains can return nodes to blocker with recommendations.

---

### 4. Cross-Product Pattern Detection (Topic 13)
**Sub-feature of Domain System.**

**Goal:** AI scans all contracts across all products, detects patterns.

**Use cases:**
- "If we change technique X to Y, how many products affected?"
- "Rollout cost/benefit analysis"
- "Who uses this deprecated pattern?"

**Requirements:**
- Well-structured flow diagrams (common language)
- Domain tags standardized
- AI pattern matching

---

### 5. Stakeholder Orchestration (Topic 11)
**Goal:** Multi-agent supervised phase.

**Flow:**
- Multiple stakeholders (humans + AI agents)
- Each domain = stakeholder
- Supervised phase = parallel discussion
- All approve → sign-off
- Any blocker → back to supervised

**Future:** Humans = just another stakeholder (AI-to-AI agreements possible).

---

### 6. Meta Diagrams (Topic 12)
**Goal:** Use contract diagrams to define pipelines themselves.

**Concept:**
- Pipeline of each domain = contract diagram
- Master pipeline = domain pipelines × nodes
- Recursive: diagrams defining diagram workflows

**Advanced:** Self-describing system.

---

### 7. Mermaid Type Support (Topic 14)
**Goal:** Support all mermaid diagram types (not just flowchart).

**Types:**
- Flowchart (default)
- Gantt charts
- Sequential diagrams
- ER diagrams
- Mind maps

**Node status/phases = universal** (works on any type).

**User experience:**
- Advanced users choose type
- Default = flowchart (simple start)

### 8. Backstage Integration (Topic 15)
**Goal:** Contract diagrams aware of epic/branch context.

**Features:**
- Auto-detect epic from branch name
- Link contract to epic tasks
- ROADMAP integration (contract = part of epic)

**Policy:**
- All epics = branch
- Contract = sandbox until checks pass
- Merge to main = snapshot only

---

### 9. Voice + Multi-Device (Topic 16)
**Goal:** iPhone chat + iPad view sync via Tailscale.

**Setup:**
- Server (Mac Studio) runs OpenClaw + wrapper
- Tailscale = remote access
- iPhone = OpenClaw chat (voice input)
- iPad = localhost wrapper (view diagram)

**Flow:**
1. Speak on iPhone → AI responds
2. AI edits diagram → iPad refreshes (hot reload)
3. Real-time sync via server

**Voice-friendly triggers:** "separa em tópicos", "muda node X pra approved"

---

### 10. Hypercare → Autonomy (Topic 18)
**Goal:** Gradual handoff from human to AI.

**Phases:**
- **Hypercare:** Everything passes through human
- **Checks mature:** AI gains autonomy
- **Certain nodes:** Always require human approval

**Guardrails:**
- Mermaid lint prevents broken diagrams
- Domain approvals mandatory
- Blocker notes required
